# 模板数据模式与多 SQL 查询：代码级审阅

**日期**：2026-09-21  
**基线**：main @ 6f8326b81540771e7bf2db9db3aa84ef57df5ea4  
**结论**：方案可实施；发现 7 个 P0、7 个 P1、1 个 P2。详细修正已回写主设计文档。

## P0

1. 现有 SQLite 没有列迁移机制，不能只修改 schema.sql。
2. PreviewModal/设计画布硬编码 sampleData，SQL runtime data 无法直接预览。
3. Browser Extension 当前只有 LIST_PRINTERS，没有 PRINT 桥接。
4. Print Agent /print 目前只是 mock accepted，不代表实体打印成功。
5. data_source_connection 的 secretRef 尚无 SecretResolver。
6. 当前没有 SQL 只读解析/执行器，不能用正则替代安全校验。
7. OpenAPI 已落后于当前模板代码，本次必须一起补齐。

## P1

1. ProblemDetail 缺稳定业务 code。
2. PrintTemplate/PrintTemplateVersion 增 dataConfig 后，service/repository/tests 构造链要一次性同步。
3. 模板导入导出目前会丢 dataConfig。
4. Undo/redo 当前只记录 design。
5. 平台 SQLite 连接池只有 1，外部慢 SQL 不能放在平台长事务里。
6. 正式 print_snapshot 当前没有 templateVersion，可追溯性要在正式 SQL 打印接入前补。
7. 默认模板仍写“门诊收费票据”，与已确认“门诊缴费票据”不一致。

## P2

- 多数据连接查询无法提供跨库全局一致快照；首期只做同 connectionId 尽量复用只读事务，不做分布式事务。

## 已冻结的契约修正

- test-data 只负责取数，不假设后端已有 HTML 渲染器。
- 前端渲染后通过 render-result 回写测试结果。
- 模拟打印复用 buildPrintDocument，不调用实体打印机。
- 插件打印增加页面→扩展→Agent 的 PRINT 消息，并通过 print-result 回写。
- SQL 已执行后的超时/失败返回 HTTP 200 + status=FAILED，以保证失败测试记录可查询。
- 静态非法请求仍使用 ProblemDetail 4xx。
- 测试业务 payload 默认不长期持久化。
